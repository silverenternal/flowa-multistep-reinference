# Wave 170 P5 — Fair-comparison FASTA evaluation (10 cells, NFE=10/50/100/200/500)

**Status:** (in progress)

**Auditor:** Wave 170 P5 (final evaluation step of Wave 170).

**Goal:** Verify whether the framework arm (`solve_ode + restart-blend`,
`n_rounds=3`, Wave 158 canonical Wave 45 multi-round path) wins
consistently over the baseline arm across the 5-cell NFE sweep
(NFE=10/50/100/200/500), on both foldability (OmegaFold pLDDT) and
self-consistency (ESM-IF1 scPerplexity) metrics.

**Cell matrix:** 5 NFE levels × 2 arms = 10 cells.
Each cell evaluates a 100-record FASTA (4 Pfam families × 25 records/family)
generated by P4.

---

## 1. CRITICAL disambiguation: what is the "baseline" arm?

The task description (STEP 2..11) instructs evaluation of:

| Arm | FASTA path | Per Wave 170 P1 audit |
|-----|------------|------------------------|
| `baseline_n1` | `…/nfe_*/baseline_n1/baseline.fasta` | **bare RNG** (no ODE solve, no restart-blend). Same as Wave 167/168 baseline. |
| `framework` | `…/nfe_*/framework/framework.fasta` | `solve_ode` at `n_rounds=3` + Wave 45 restart-blend glue. |

This is the **bare-RNG vs solve_ode+restart** comparison from Wave
167/168. It is NOT the strict JMAA-fair comparison
(`n_rounds=1` vs `n_rounds=3`), which the Wave 170 P1 audit identifies
as the only theoretically fair reference. **The strict JMAA-fair
comparison is byte-identical at every NFE** under synthetic mode (see
§2 below), so an empirical JMAA-fair evaluation cannot disambiguate
the restart-blend value-add. The empirical result here therefore
compares **bare RNG (no ODE) vs solve_ode + restart-blend at
n_rounds=3**, which should show framework > baseline on pLDDT and
framework < baseline on scPerplexity (lower is better).

This audit acknowledges the discrepancy and reports empirical results
for both interpretations (§4 below).

## 4. Interpretation

**Framework does NOT win consistently across all 5 NFE levels** (on
the Wave 167/168-style comparison per the task's STEP 2..11 FASTA
choices).

* **pLDDT (foldability, higher better):** Framework wins only at
  NFE=10 (+1.87). At NFE=50/100/200/500 the framework arm is
  **worse** on pLDDT by ~0.85–1.57 (negative ΔpLDDT). 4 out of 5 NFE
  levels favour the bare-RNG baseline on this metric.

* **scPerplexity (self-consistency, lower better):** Framework wins
  consistently at all 5 NFE levels (Δ in [-3.99, -3.08]). All 5
  deltas are negative, so the framework arm produces sequences whose
  self-consistency (ESM-IF1 inverse-folding perplexity) is uniformly
  lower than the bare-RNG baseline.

pLDDT deltas (framework - baseline, higher better):
  `[+1.87, -0.85, -1.40, -1.35, -1.57]`
scPerplexity deltas (framework - baseline, lower better):
  `[-3.99, -3.39, -3.15, -3.08, -3.16]`

`framework_wins_consistently = False` (pLDDT flips sign at NFE≥50).

**Reading.** The framework arm at NFE≥50 produces sequences that
are **better-conditioned for ESM-IF1 inverse folding** (scPerp drops
by ~3) but fold into OmegaFold-predicted structures whose
per-residue pLDDT is **lower** than the bare-RNG baseline by ~1.
This is consistent with the framework generating "smoother" sequence
distributions that ESM-IF1 recognises as more protein-like, but which
OmegaFold (a single forward pass, no SC refinement) scores slightly
less confidently than the bare-RNG sequences. The pLDDT metric is
known to be sensitive to structural features (OmegaFold's
secondary-structure prior dominates at typical sequence lengths)
that do not directly reflect sequence quality.

**Caveat 1 (test-surface limitation):** Under the synthetic velocity field, `baseline_n1/framework.fasta` (n_rounds=1) and `framework/framework.fasta` (n_rounds=3) are byte-identical (Wave 170 P4 §2.2). The strict JMAA-fair comparison therefore yields Δ=0.00 at every NFE level; only the bare-RNG-vs-solve_ode+restart comparison (the task's STEP 2..11 FASTA choices) is empirically informative here.

**Caveat 2 (paper disclosure):** Per Wave 169 P5 §2.9, the paper **must** disclose that `n_rounds=1` vs `n_rounds=3` is byte-identical under synthetic mode, so the restart-blend value-add cannot be empirically disambiguated without a torch-mode LineageFlow adapter (out of scope for this CPU-only wave).

## 5. Reproduction

```bash
# Prereq: P4 FASTAs already exist at /tmp/w170/fastas/nfe_{10,50,100,200,500}_{baseline_n1,framework}/
# CUDA-enabled env with OmegaFold + ESM-IF1
export PATH=/home/hugo/.conda/envs/omegafold_py310/bin:$PATH
cd <repo_root>

# Eval baseline_n1 (bare RNG) at all 5 NFE levels
for nfe in 10 50 100 200 500; do
  python data/lineageflow_upstream/evaluation/evaluate_all.py \
    --metrics foldability self_consistency --max-seqs 100 \
    --fasta /tmp/w170/fastas/nfe_${nfe}_baseline_n1/baseline.fasta \
    --outdir /tmp/w170/eval/baseline_n1/nfe_${nfe}/
done

# Eval framework at all 5 NFE levels
for nfe in 10 50 100 200 500; do
  python data/lineageflow_upstream/evaluation/evaluate_all.py \
    --metrics foldability self_consistency --max-seqs 100 \
    --fasta /tmp/w170/fastas/nfe_${nfe}_framework/framework.fasta \
    --outdir /tmp/w170/eval/framework/nfe_${nfe}/
done

# Aggregate
python /tmp/w170/aggregate.py
python /tmp/w170/make_plot.py
```
