# Wave 274 P7 — MANIFEST.md self-referencing SHA resolution

**Problem:** MANIFEST.md row 21 documents its own file's SHA-256 + size.
Each edit re-hashes itself, so the literal value changes after every
write. Self-referencing a SHA-256 inside the same file is therefore
impossible without an external witness.

**Resolution:** the `MANIFEST.md` row 21 now carries a `<see-bottom>`
placeholder that names this sidecar doc as the authoritative post-edit
SHA + size source. Reviewers who want the **current** MANIFEST SHA
must run:

```bash
sha256sum tnnls_submission/MANIFEST.md
wc -c tnnls_submission/MANIFEST.md
```

**Why this sidecar exists:**
- Per Wave 268 strict-clean principle, no SHA may be falsified inside
  a file that owns its own hashing cycle.
- The cleanest fix is the one-line placeholder in MANIFEST.md plus this
  sidecar audit. The placeholder is regenerated by anyone running
  `sha256sum` post-merge.
- TNNLS reviewers who download `tnnls_submission/MANIFEST.md` can
  re-verify the placeholder by running the two-line command above.

**Why the SHA-256 itself is NOT recorded inside this sidecar:**
- The same self-reference problem applies here: this file's SHA is
  captured by a different sidecar (`docs/audit/wave274-p8-self-sha.md`).
- The cleanest approach is: describe the procedure, name the sidecar
  chain, and let reviewers regenerate. No SHA may be hard-coded inside
  its own hashing cycle.
