## 3. Algorithm Coupling Map

**Default path** (no opt-in switching):
`CosineAnnealScheduler.sample → ScheduleSample → ScheduleDerivedPolicyDriver.compute_policy (β = n_cap)`
→ `BoundedMergeOperator.merge (with prev, dynamic, cap = n_cap, floor, delta_caps)` → `LinearBlender.blend (m = 1 − β)`
→ adapter writes a fresh endpoint → `ModeCentreMSEW2.estimate → TwoDimFMEvaluator` → `EnergyDistance / Coverage / Selection Ratio` → `ReInferenceRunner` per-round metrics → `RoundToRoundOscillationDetector`.

**Opt-in instruments**: every other algorithm in §1 is reachable via `PROTOCOL_REGISTRY` + `to_config/from_config` round-trip and the `selection_evaluator`, `paper_quantities_provider`, `selection_w2_family`, `inject_noise_strategy`, etc. switches on `ReInferenceConfig`.

```
                       ┌─────────────────────────────────────────────────────────────┐
                       │                  CONTRACT BOUNDARY (per-round)              │
                       │                                                             │
   ┌──────────────────────────┐    ┌──────────────────────────┐    ┌──────────────────────────┐
   │  Scheduler layer (S1–S15)│    │  PolicyDriver layer (PD) │    │  MergeOperator layer (M)  │
   │  default: CosineAnneal   │    │  default: ScheduleDeriv. │    │  default: BoundedMerge    │
   └────────────┬─────────────┘    └────────────┬─────────────┘    └────────────┬─────────────┘
                │ sample (ScheduleSample)       │ compute_policy (β=n_cap)        │ merge(prev,dyn)
                ▼                              ▼                                 ▼
   ┌──────────────────────────────────────────────────────────────────────────────────────────────┐
   │ adapter adapter adapter   TwoDimFMAdapter (apply_restart_distribution)                       │
   │ └── Integrator (default RK4; opt-in I3–I12)                                                  │
   │ └── KarrasPreconditioner (opt-in)                                                            │
   └────────────────────────────┬─────────────────────────────────────────────────────────────────┘
                                │ endpoint_state
                                ▼
   ┌──────────────────────────────────────────────────────────────────────────────────────────────┐

   └────────────────────────────┬─────────────────────────────────────────────────────────────────┘
                                │ blended StateBundle
                                ▼
   ┌──────────────────────────────────────────────────────────────────────────────────────────────┐
   │ ReInferenceRunner → TwoDimFMEvaluator                                                        │
   │   ├── W2 family: default ModeCentreMSEW2 ; opt-in W22–W27                                    │
   │   ├── coverage:    default coverage_score (binary); opt-in C1 weighted, C5 KDE, C6/C7        │
   │   ├── posterior:   EvidenceScaleGapMetric (selection_ratio = sheet/(sheet+cell))             │
   │   ├── lipschitz:   default lipschitz_modulus; opt-in bounded_lipschitz_distance,            │

   │ Engine ledger (audit) → diagnostics (observation-only ledger types) → claim_gate → promotion  │
   └──────────────────────────────────────────────────────────────────────────────────────────────┘
```

The four **protocols** (`SchedulerProtocol`, `PolicyDriverProtocol`, `MergeOperatorProtocol`, `RestartBlenderProtocol`) are reachable by name through `PROTOCOL_REGISTRY` (`adaptive_reflow/algorithm/protocol_registry.py:267`). `W2_REGISTRY` (`w2.py:1086`) gates the W2 family. `INTEGRATOR_REGISTRY` (`integrators.py`) gates the integrator family. `ROTATION_POLICY_REGISTRY` (`rotation_policy.py:198`) gates rotation policies.

The **paper-quantity wiring** (`paper_quantities.py`) feeds:
1. `CodimensionSheetScheduler` via cached `sheet_A / packing_B / cell_C / exterior_gap_e_rho`;
2. `AdaptivePolicyDriver` via `per_cell_coefficient_C`;
3. `BoundedMergeOperator` via `exterior_gap_e_rho` floor lift;
4. `EDMScheduler.inject_noise` via `exterior_gap_e_rho / 4` floor;
5. `ReInferenceRunner.paper_quantities_provider` callback.

These are the **only** five algorithms that consume paper quantities. Every other reference is "framework-side heuristic" per `evidence_driver.py`.

## 6. Algorithm Smells

The following smells are catalogued; the code is NOT modified.

### 6.1 Duplicated logic / near-duplicate implementations

1. **`HandoffSequentialScheduler` exists in TWO files** (`adaptive_reflow/algorithm/sequential_handoff.py:50` and `adaptive_reflow/algorithm/handoff.py` defines a `HandoffSequentialScheduler`). The `__all__` of `handoff.py` does not export it, but `seq_inject_noise_fallback` audit code is emitted from `SequentialScheduler.inject_noise` (line 408 in `sequential.py`), not from the handoff subclasses. Both modules import `SequentialScheduler` and re-wrap. Consider one canonical.
2. **`JointOTLinearBlender` and `BarycentricBlender` define `FAMILY: str = "..."` while canonical `LinearBlender` and `DistanceDecayBlender` define `FAMILY: ClassVar[str]`.** Two different idioms for what is semantically the same constant; the constructor protocol-style dataclasses (`ParallelRunner`, `EarlyStopRunner`, etc.) also use `ClassVar`. Mixing hurts introspection.
3. **Two copies of `W2BarycenterCoverage`** at `eval/coverage_extra.py:269` and `eval/coverage_r2.py:345`. `coverage_r2.py` is described as the registry-style variant; the older `coverage_extra.py` carries the implementation. Two maintenance surfaces for one algorithm.
4. **Two implementations of `support_coverage_score`** at `eval/coverage_extra.py:103` and `eval/coverage_r2.py:126`. Same algorithm; the file header of `coverage_r2.py` even says it is a re-rollout.
5. **Two implementations of `top_k_coverage_with_entropy`** in the same pair of files (`coverage_extra.py:184`, `coverage_r2.py:272`).
6. **`_paper_evidence_balance` heuristic path uses `(1 - n_cap_base)**2 * eps**2` weighted by a *framework-side heuristic*, then the paper-quantity-augmented path uses `cell_C * packing_B * eps**2`.** The docstring (`scheduler.py:2200-2252`) admits the `(1 - n)` term has no paper counterpart; the heuristic and the paper-quantity-augmented paths agree on direction but not on the cell-side weight. Two paths, identical interface, different magnitudes.
7. **`AdaptivePIDScheduler.record_round_feedback`** computes the integral term by reconstructing a blended time series from per-metric histories (`scheduler_extra.py:716-742`) instead of maintaining a streaming accumulator. The two code paths (single-metric vs multi-metric) produce different `_loss_history` updates, an asymmetry that is non-obvious.
8. **`_canonicalize` and `_canonical_json_default`** are duplicated near-verbatim in `policy_driver.py` (`_stable_digest`, lines 774–848) and in `blender.py` (`_canonical_json_default`, line 721), despite the docstring of the latter explicitly calling out the duplication as deliberate.

### 6.4 Unclear contracts / no Protocol conformance check

1. **`IntegratorProtocol` has a `@runtime_checkable` decorator at `integrators.py:42` BUT the `SDEIntegratorProtocol` is a separately-decided runtime check at line 715.** No code asserts `isinstance(integrator, IntegratorProtocol)`; adapters duck-type. The runner accepts `integrator` without validating.
2. **`W2EstimatorProtocol` is `@runtime_checkable`** (`w2.py:135`). The `compute_w2(...)` helper at `w2.py:1109` calls `estimator.estimate(...)` and `estimator.family`, but no `isinstance` guard exists in `compute_w2`.
3. **`SchedulerProtocol`, `PolicyDriverProtocol`, `MergeOperatorProtocol`, `RestartBlenderProtocol`** are `@runtime_checkable` BUT the runner wires them with no `isinstance` check; the construction site (`_build_scheduler_registry` in `protocol_registry.py`) relies on the lazy-import side effects.
4. **`BoundedMergeOperator.exterior_gap_e_rho`** is a paper-quantity plumbing field; its constructor accepts `None` or a positive float, but the protocol `MergeOperatorProtocol.merge` does NOT advertise `exterior_gap_e_rho` so it cannot be propagated through the protocol. The merge operator carries paper-quantity state via the instance, NOT via `merge(...)` arguments. This is a contract leak.
5. **`EMAOperator.merge` extends the canonical protocol signature with `schedule_sample: Any | None = None`** (`merge_operator.py:753`). This kwarg is not part of `MergeOperatorProtocol`; callers using `merge(...)` over the protocol cannot pass `schedule_sample`. Anyone running `merge(operator, ...)` over `MergeOperatorProtocol` will silently lose the schedule-awareness. The "schedule-aware EMA" only works if the caller statically knows the type.
6. **`MultiSourceKalmanMergeOperator.merge` also extends `dynamics` keyword**. Same `Protocol` boundary issue: `MergeOperatorProtocol.merge` doesn't carry `dynamics`.
7. **`BoundedMergeOperator`, `EMAOperator`, `IdentityOperator` are NOT decorated `@runtime_checkable`** themselves; they rely on duck typing. `MergeOperatorProtocol` IS `@runtime_checkable`, but the implementations don't declare inheritance. The `isinstance(op, MergeOperatorProtocol)` works via runtime structural typing.
8. **`ScheduleSample.evidence_ratio`** is a field added later (P0-A7). Every scheduler has to set or omit it. `SequentialScheduler` forwards via `getattr(...) or None` (`sequential.py:285`), which means any sample without it silently loses the evidence context.
9. **`AdaptivePolicyDriver.beta_saturation_count`** is a runtime counter that escapes the dataclass equality. Two drivers with the same config but different counts compare equal (`config_hash` ignores it). This breaks the "every construction argument appears in `config_hash`" convention used elsewhere.
10. **`CodimensionSheetScheduler.eps_direction = "increasing"`** is kept for back-compat with a `DeprecationWarning` emitted only on `sample()` (P2-18, `scheduler.py:2651`). This means a constructor that never `sample`s produces no warning, and silent misconfigurations can persist.

Documentation describes the default as "the bounded merge without paper-quantity floor". A user reading the module-level docstring might assume all bounded merges use `e_rho`.

## Smells

The smells observed in this inventory (cross-referenced to §6 sections):

- **High-impact duplication**: two `HandoffSequentialScheduler` files (§6.1.1); two `W2BarycenterCoverage` files (§6.1.3); two `support_coverage_score` / `top_k_coverage_with_entropy` pairs (§6.1.4, §6.1.5). Maintenance surface 4× for two algorithms.
- **Protocol boundary leaks**: `EMAOperator.merge`'s `schedule_sample` kwarg and `MultiSourceKalmanMergeOperator.merge`'s `dynamics` kwarg cannot be invoked through `MergeOperatorProtocol` (§6.4.5, §6.4.6). The "schedule-aware" merge is invisible to callers over the protocol.
- **Phantom registry keys**: `SCHEDULER_FAMILIES` declares 5 families that have no implementation (`warmup_linear`, `geometric`, `piecewise_sigmoid`, `handoff`, `handoff_sequential` — wait, `handoff_sequential` IS implemented). Net 4 dead families advertised in the schema (§6.6).
- **Paper-grounded but actually framework-side heuristic**: `CodimensionSheetScheduler.evidence_ratio` falls back to a heuristic when `profile_residual_fn is None` (§6.5.1); `AdaptivePolicyDriver.beta = (1 - |p - t|)` drops `C_g` normalisation when `per_cell_coefficient_C is None` (§6.5.2). These two heuristics are the algorithms' load-bearing quantities and they silently differ from the cited paper.
- **Algorithm-without-caller**: 15 algorithms are registered / exported but have no caller in the default runner path (rotation policies, sequential handoff, jittered schedulers, OT / barycentric blenders, Bayesian / Kalman merge variants, AMSGrad-style saturation counter).
- **Weakly tested**: 14 algorithms have only happy-path / round-trip tests and no edge-case coverage (rotation policies, schedule-aware EMA, multi-source Kalman mismatch, symplectic integrator volume preservation, kernel Lipschitz degeneracies, evidence-driven identity, etc.).
- **Audit counters escape equality**: `AdaptivePolicyDriver.beta_saturation_count` and `SequentialScheduler._audit_codes` are mutable runtime state that does not appear in `config_hash`, so two instances with different counts compare equal. Breaks the "every construction argument enters config_hash" pattern.
- **Deprecated path silently reachable**: `CodimensionSheetScheduler(eps_direction="increasing")` emits a `DeprecationWarning` only on the first `sample()`, not at construction (P2-18). Constructors can be silently mis-wired for as long as the scheduler is never exercised.
- **Algorithm-density surprise**: 78 algorithm-bearing classes in `adaptive_reflow/**` (60 callable + 18 supporting); 9 are default-path. Opt-in ratio is 7.6:1 (69 opt-in : 9 default), a signal that most of the surface is paper-grounding scaffolding rather than active policy.

**Biggest smell**: the **phantom-registry / paper-grounded-but-heuristic** combination in `CodimensionSheetScheduler` (§6.5.1 + §6.6). The scheduler family is the project's signature contribution, yet with no `profile_residual_fn` it produces a `[0, 1]` evidence ratio whose magnitude is a *framework-side heuristic* that the docstring admits has no paper counterpart. The diagnostic (`warn_if_heuristic_evidence_mode`) exists precisely for this case but no caller wires it into the default runner, so a user who instantiates `CodimensionSheetScheduler(eps_implicit=0.05)` from `protocol_registry.py` (the polymorphic dispatcher) gets a "paper-grounded" surface that returns heuristic numbers and never warns.
