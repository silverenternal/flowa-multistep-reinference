## 3. Interpretation

### 3.1 Why a separate file (not just longer "Maintenance" section in INDEX.md)

The 4-line Maintenance section at the bottom of `docs/audit/INDEX.md` is the right place for the **TL;DR** but not for the **full pattern doc** — INDEX.md is itself regenerated by the script, so any long docstring inside it would be at risk of being clobbered by the next regen run. A separate top-level file (`docs/audit/INDEX_MAINTENANCE.md`) is:

- Stable across regen runs (only this one maintenance doc explicitly references the regen script; the regen script's fallback cluster is `governance` so INDEX_MAINTENANCE.md will be reclassified under governance on the next run — see §3.2)
- Deep-linkable from wave audit docs and from the TNNLS submission package
- Grep-able for keywords like "ACTIVE_SURFACES", "regen_index.py", "cluster assignment"

### 3.2 Expected behavior on next regen run

When `/tmp/regen_index.py` is re-run after Wave 358 P3, it will:

1. Walk `docs/audit/` and find `INDEX_MAINTENANCE.md` at the top level (it is not `INDEX.md` so it is included in the file list).
2. Run Pass 1 (filename match): none of `INDEX_MAINTENANCE.md`'s lowercase contents match any cluster's filename keywords → no match.
3. Run Pass 2 (content match for `mode='any'` clusters): the first 40 lines of INDEX_MAINTENANCE.md mention words like `cluster`, `active`, `governance`, `TNNLS`, etc. — but no exact keyword from any `mode='any'` cluster's keyword list (the cluster keyword lists are short and topic-specific).
4. Fallback: `governance`.

So `INDEX_MAINTENANCE.md` will appear under the `governance` cluster in the next regen run. This is **acceptable** because:
- It is, semantically, a governance doc (it documents the governance pattern for the index itself).
- The first paragraph of INDEX_MAINTENANCE.md says explicitly: "This file is intended to make the regen logic legible without reading Python" — which is a governance-framing statement.
- The cross-link from INDEX.md's Maintenance section to INDEX_MAINTENANCE.md is preserved across regen runs (the Maintenance section is hand-maintained, not regenerated).

### 3.3 What a reviewer gains

A reviewer who opens `docs/audit/INDEX.md` can now:

1. Read the 4-line Maintenance TL;DR → click through to `INDEX_MAINTENANCE.md`.
2. In INDEX_MAINTENANCE.md: understand what the Active/Historical flags mean, how cluster assignment works, how to add a new audit file, and how to re-run the regen script — without opening `/tmp/regen_index.py`.
3. Cross-reference `/tmp/regen_index.py` if they want to verify the documented behavior matches the implementation.

This is the standard pattern for self-documenting repos: a top-level hand-maintained file documents the auto-generated artifact. The auto-generated artifact (INDEX.md) points at the hand-maintained file.
