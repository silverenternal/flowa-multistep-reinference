## CRITICAL: Premise Correction Up Front

The P4 task description (Wave 167 P4) states:

> "P3 produced 8 cells at NFE=50/100/200/500 baseline + framework"

**This premise is false.** Per `docs/audit/wave167-p3-eval.md` §1c + §2 + §4
and the underlying filesystem state at `/tmp/w167/eval/{baseline,framework}/`:

- **Cells P3 actually evaluated:** 1 of 8 (only NFE=10, baseline + framework)
- **Cells NOT evaluated:** 7 of 8 (NFE=50/100/200/500 × 2 arms blocked by
  P2 root cause: gen script lacks `--nfe` flag; FASTAs were never generated)

The P4 task description also assumes Wave 161 K6's N=1000 sweep used
**NFE=1000**. **This is also incorrect** — the Wave 161 K6 sweep FASTAs
were generated by Wave 158 (`/tmp/w158/lineageflow_real_fastas/manifest.json`)
at **`nfe_per_record: 10`** (the "N=1000" refers to records, not NFE budget).
So both the P3 measurement (N=100) and the K6 measurement (N=1000) are at
**the same NFE level (NFE=10)**.

**Result:** the actual measured data set is **one NFE point (NFE=10) at two
N values (N=100, N=1000)** — an **N-axis** measurement at a fixed NFE,
**not an NFE curve**.

This audit reports the honest artefact (an N-axis plot at fixed NFE=10) and
discloses the gap from the P4 task description's premise (9 NFE points at
5 NFE levels × 2 arms).

characterized from a single NFE point.

issue (1/4 NFE points measured) and reached the same conclusion. Wave 166b
P4 (`docs/audit/wave166b-eval.md` / §10.11 paper-draft ADDITIVE correction

## 5. Interpretation

1. **The framework produces a real, reproducible, directionally stable
   improvement on both metrics** at the only NFE level measured (NFE=10):
   - pLDDT: +1.12 to +1.87 (framework higher)
   - scPerplexity: ~−22% relative (framework lower, better)
2. **The N-axis observation at fixed NFE=10 shows** framework advantage
   **preserved across N** (N=100 → N=1000, deltas shrink modestly in pLDDT
   absolute terms but stay stable in scPerplexity both absolute and
   relative). This is a **statistical-power-consistent** result (larger
   N reduces noise, which can shrink point-estimate gaps while keeping
   relative improvements stable).
3. **The NFE-axis observation is empty** — no NFE=50/100/200/500 data
   exists on disk. The P4 task description assumed 8 cells that were never
   generated.
4. **The camera-ready canonical reference remains Wave 166b P4 §10.11
   ADDITIVE correction** (`docs/paper-draft.md` at commit 5108013, which
   explicitly notes the same time-budget blocker and the same follow-up
   recipe).
