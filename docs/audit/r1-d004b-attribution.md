## 0. TL;DR

The D-004b R1 real-forward win (framework 275/272/259 vs baseline 158/159/174)
was **not yet mechanism-attributed**: the D-004b fix gave the restart fresh state
a per-record random simplex, so the win could be either the multi-round
restart-blend **or** the per-record stochastic init alone. This increment runs
the missing control.

**Result: the win is the per-record random initial state, not the restart-blend.**

| seed | A baseline | B init-only | C framework | B − A | B − C |
|---:|---:|---:|---:|---:|---:|
| 42 | 158 | **298** | 275 | +140 (+0.194 d_z) | +23 (+0.029 d_z, n.s.) |
| 43 | 159 | **274** | 272 | +115 (+0.168 d_z) | +2 (+0.003 d_z, n.s.) |
| 44 | 174 | **290** | 259 | +116 (+0.161 d_z) | +31 (+0.040 d_z, n.s.) |
| **pooled** | | | | **+123.7 hits** (t=15.13, p=0.0043) | **+18.7 hits** (t=2.16, p=0.16, n.s.) |

A single model pass from a per-record random initial state (**B**) already
matches — indeed slightly *exceeds* — the full 3-round restart-blend framework
(**C**), and both dominate the canonical baseline (**A**). The restart-blend
contributes **≈ 0** over the random init (pooled B−C per-record $d_z$ ∈
[+0.003, +0.040], none significant).

**R1 verdict: retained PARTIAL, now with the attribution disclosed.** The
real-forward *win* is real, but it is a win of the **per-record stochastic
init**, not of the framework's restart-blend mechanism.

## 3. Interpretation

The three-way decomposition:

- **B ≈ C** (pooled difference +18.7 hits, n.s.; per-record $d_z$ ≤ +0.04).
  A **single pass from a per-record random initial state** reproduces the
  entire framework win. The multi-round restart-blend adds nothing measurable
  over it (it is, if anything, a hair *lower* than B on every seed).
- **B > A** strongly (pooled +123.7 hits, $p = 0.0043$).
- **C > A** (the recorded win) is therefore **entirely carried by the
  per-record stochasticity**, which both B and C inject — B via the initial
  state, C via the restart fresh state.

**Consequence for R1.** The R1 real-forward cell is a genuine *win over the
baseline*, but it is **not evidence for the framework's restart-blend
mechanism** on this cell. The mechanism the win isolates is *per-record
stochastic initialisation* — the D-004b surrogate, which the D-004b audit
already flagged as a tool convention, not the upstream intervention sampler.
This is the honest reading the D-004b caveat asked for.

**What this does *not* say.** It does not refute the restart-blend on other
cells (R2/R6/K4/K5 have their own mechanisms), and it does not change the
recorded D-004b numbers. It only relocates the *attribution* of the R1 win.

## 4. Verdict

**R1 (LineageFlow HMMER, real-forward):** retained **PARTIAL**, with the
mechanism now disclosed.

- The real-forward basis is a **win over the baseline** (C > A; D-004b recorded).
- The win is **attributable to the per-record random initial state**, not the
  multi-round restart-blend (B ≈ C; B ≫ A).
- R1 is **not** promoted to STRONG on the strength of the restart-blend; the
  small-effect PARTIAL classification stands, now with a precise mechanism.

No frozen surface is edited. The D-004b `caveat` field in `todo.json` (which
said the attribution was "NOT yet run") is updated to point here.
