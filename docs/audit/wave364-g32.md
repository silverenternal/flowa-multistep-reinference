## 3. Interpretation (why this closes G32)

The cover letter §0 opening header is the first thing the TNNLS editor reads after the salutation block (§0 USER ACTION REQUIRED placeholders). The original header carried a single `**Date:** 2026-09-21` placeholder — a soft target that the corresponding author would edit at ScholarOne upload time. Between Wave 322 (cover letter freeze) and Wave 364, the manuscript underwent six major data-rebuild waves (Wave 343 bibliography fix, Wave 348 GitHub-URL cross-doc fix, Wave 351 Theorem-5 numerical validation, Wave 352 Theorem-5 Lipschitz derivation, Wave 353 Theorem-4 derivation + framework-code-anchors, Wave 358 P4 tables-md polish); the Wave 358 P4 totals in particular updated the R-level tables in §6 / §15 of the manuscript. The cover letter §0 date, however, was not refreshed to reflect this — so a reviewer reading the cover letter and the manuscript would see a cover-letter date (2026-09-21) older than the manuscript's most-recent artefact (Wave 358 P4 ≈ 2026-09-25 by the WAVE 358 timeline), creating a minor inconsistency at the top of the submission package.

The G32 fix resolves this inconsistency by adding a parallel `Last internal draft refresh` field that:
- Anchors the cover-letter timing to the Wave 358 P4 totals rebuild (the most recent paper-data artefact refresh).
- Disclaims that the final submission date is set at ScholarOne upload (so the 2026-09-25 date is the *internal draft* marker, not a ScholarOne upload claim).
- Preserves the corresponding-author's action surface (the 2026-09-21 placeholder is still the editable line, and all 17 USER_TO_FILL placeholders are untouched).

The corresponding-author's ScholarOne-upload action sequence is therefore unchanged: at upload time, the author edits `**Date:** 2026-09-21` → `**Date:** <ScholarOne upload date>`, fills the 17 USER_TO_FILL placeholders per `FILL_GUIDE.md`, and the `Last internal draft refresh` field remains as a provenance marker for the Wave 358 P4 totals refresh (this Wave 364 G32 ADDITIVE).
