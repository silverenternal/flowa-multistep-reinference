## 3. A claim that had quietly become false

The manifest opened with:

> This manifest enumerates **every file that is git-tracked** under
> `verification_outputs/` (439 files).

True on 2026-09-22. False now: `git ls-files verification_outputs/` returns
**41,561** files. The catalogue covers 1.1% of the tree, and the tree keeps
growing because every sweep commits its sample shards.

Regenerating with `tools/build_verification_manifest.py` is not the fix — it
would emit 41,561 rows, and the per-directory `SHA256SUMS` ledgers already
cover the new material. The header was rewritten to say what the file
actually is: a curated catalogue of the 439 files that back a headline
number, with a pointer to the per-directory ledgers for everything after it.
The verification instruction ("the hash listed MUST match") is unchanged and
is now enforced.

## 6. Deliberately not done

- **The catalogue was not regenerated.** 41,561 rows would be unreadable and
  would duplicate the per-directory ledgers. The honest fix was to correct
  the scope claim, not to inflate the file.
- **`tools/build_verification_manifest.py` was not run.** It is still correct
  with respect to its own spec; running it is a packaging decision, not an
  audit fix.
- **The `Size (bytes)` column is not checked independently.** A matching
  SHA-256 over the file's bytes already implies the size; a separate check
  would only re-read the same bytes.
- **Historical audit records that quote the old digests were left alone.**
  `docs/audit/wave252-p4-verification-manifest.md` and the Wave 328 freeze
  survey describe the manifest as it stood; rewriting them would falsify the
  trail.
