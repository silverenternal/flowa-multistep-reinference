## Observed implementation

1. The CIFAR headline driver `tools/run_sota_cifar_experiment.py:841-925` constructs a starting bundle and passes each observed endpoint bundle to the next `Engine.run_round`. Its `n_rounds=1` case calls the engine at `r=0`; it has no preceding endpoint. With `--match-nfe sample`, `steps_by_round` sums to the baseline's NFE (`:821-830`).
2. `Engine.run_round` receives that bundle, but `adaptive_reflow/frame/engine.py:1770-1800` calls `adapter.build_initial_state` again using only its batch/sample IDs. It passes **this newly built state** to `adapter.apply_restart_distribution` at `:1874-1881` and then to `solve_ode` through the returned post-state. The passed endpoint bundle contributes to gates, provenance and hashes, but is not the numerical prior for this restart call.
3. `RectifiedFlowCIFARAdapter.build_initial_state` (`adaptive_reflow/adapters/rectified_flow_cifar.py:865-900`) deterministically constructs an image-like initial tensor from batch/sample IDs. Its `apply_restart_distribution` (`:954-1020`) blends that state's `x0` with a policy-seeded fresh image-like tensor. Thus the CIFAR headline's numerical input is a **fresh/initial-state blend**, including at `r=0`; this path does not instantiate $m x_{r-1}^{\mathrm{endpoint}}+(1-m)b_r$.
4. The MNIST headline driver `scripts/wave191_p3_mnist_sweep.py:291-322` has a different direct-adapter path: it builds one initial state at `r=0`, solves and observes an endpoint, and for each `r>0` applies restart to that endpoint bundle before the next solve. `MnistFmAdapter.apply_restart_distribution` (`adaptive_reflow/adapters/mnist_fm.py:613-680`) blends the bundle's `x0` with policy-seeded Gaussian noise. This path does instantiate endpoint feedback for later rounds. Its first round has no restart.
5. `docs/audit/wave336-r5b-mechanism.md` says the CIFAR fresh term is a newly computed endpoint and attributes the first-round benefit to residual-error extraction. That description conflicts with the execution path above. The audit's FID observations remain measurements; its causal interpretation does not follow from this code path. `docs/audit/mnist/wf334-r5c-regime-curve.md` compares settings that change architecture and data in the first transition and uses one seed in the intermediate setting, so it does not isolate training maturity as a cause.

## Interpretation and paper impact

The composite feedback equation is a useful **reference model** and describes the direct MNIST multi-round loop after round zero. It does not describe the CIFAR headline's numerical state transition. The CIFAR single-round FID differences therefore cannot establish a benefit from endpoint feedback; they compare a changed initial distribution and a particular NFE/schedule/evaluator protocol. Extra-round CIFAR regressions are likewise not evidence of accumulated endpoint mixing on this engine path. Theorem 4 (feedback contraction) and Theorem 5 (blend identity with the preceding endpoint as $X$) should not be presented as explanations of R5b without a driver that actually uses that endpoint as its numerical prior and per-round target measurements. Ledger continuity is not a substitute for numerical state continuity.

## Unresolved gaps and smallest next action

- Instrument the numerical `x0` passed to `solve_ode` in a bounded, checkpoint-free engine probe, and compare it with the previous endpoint digest/state. This source-level result is already decisive for the inspected CIFAR adapter, but a probe would guard future refactors.
- Run a matched-NFE CIFAR factorial under **one checkpoint, seed policy and evaluator**: endpoint carry on/off × restart blend on/off × per-round NFE allocation. Preserve separate $N=200$ and $N=1000$ reporting and use FID bootstrap or repeated-seed uncertainty rather than treating per-image feature-distance tests as FID tests.
- For MNIST, hold architecture/data fixed across checkpoints and measure the actual blend inputs and outputs. A contraction estimate or target-space error is needed before calling its sign flip a verified contraction or residual-correction mechanism.

**Readiness consequence:** the current eight-page PDF can better explain its gains by separating the measured SOTA integration pathways from the endpoint-feedback reference model. A future image mechanism section should distinguish the two execution paths and reserve causal endpoint-correction claims for controlled ablations.

The generic protein evaluation helper `tools/eval/framework.py:753-858` deserves its own protocol accounting before it is used as a causal proof: `export_endpoint(cur_bundle)` is an identity pass-through for Kanzi and LineageFlow (`adaptive_reflow/adapters/{kanzi,lineageflow}.py`), while their endpoint extraction lives in `observe_endpoint(trace,state)`. This helper also makes a final `solve_ode` call at full requested NFE after the per-round solves. Consequently, a `nfe=50` argument there does not by itself mean **50 total physical field evaluations**. The positive measured protein effects remain valid for their recorded protocol; matched-compute and endpoint-feedback mechanism claims require an explicit call-count and state-path audit for each headline driver.
