Top 10 most impactful¶

  1. Finding #15 — CodimensionSheetScheduler._paper_evidence_balance is non-monotone in n_cap. The audit-trail ratio starts at 1.0 (round 0) and ends at < 1.0 (terminal), so the Theorem-1 "selection_ratio → 1" witness goes the wrong direction. This is the framework's signature paper-grounded algorithm; its core metric moves the wrong way. (Sev 3)
  2. Finding #12 — Framework-side heuristic evidence_ratio is paper-labelled. CodimensionSheetScheduler.evidence_ratio is reported as a ScheduleSample.evidence_ratio in both wired and heuristic paths, and EvidenceScaleGapMetric reads it without checking which path produced it. The Theorem-1 witness is not a Theorem-1 witness in the default path. (Sev 3)
  3. Finding #3 — Forward-noise injection is computed and discarded. The runner advances the np.random.Generator state by one draw per round, then drops the result. The "DRM-3 symmetric round" claim is forward-asymmetric, reverse-inlined, with the forward side purely cosmetic. Affects every ReInferenceRunner.run. (Sev 2)
  4. Finding #1 — MERGE_PREV_ANCHORED_TO_LAST_EMITTED is a never-emitted audit code. The constant is public, re-exported, and the audit-trail-of-record contains zero hits on the production data path. Audit-trail readers filtering on this code see nothing. (Sev 2)
  5. Finding #5 — BoundedMergeOperator silently swaps cap and floor on inversion. A user error is masked: cap=0.2, floor=0.8 is silently inverted to cap=0.8, floor=0.2, widening the envelope. The fail-closed contract is violated. (Sev 2)
  6. Finding #4 — SCHEDULER_FAMILIES advertises 4 phantom keys (warmup_linear, geometric, piecewise_sigmoid, handoff). validate_config_schema accepts them; build_scheduler_from_config raises KeyError. Schema validation succeeds, dispatch fails. (Sev 2)
  7. Finding #8 — selection_ratio is recorded but never fed back to the algorithm. Loop 2 (paper quantities → scheduler) is documented as a feedback loop; the runner only feeds W2/coverage back. The metric is observation-only, half-closing the loop. (Sev 2)
  8. Finding #11 — MergeOperatorProtocol has 8 implementations; the runner uses 1. EMA, Identity, Kalman, Bayesian, PID, ScheduleAware, MultiSourceKalman are unreachable from ReInferenceRunner and BatchedTrajectoryRunner. The polymorphic surface is a no-op. (Sev 2)
  9. Finding #23 — build_scheduler_from_config ignores kwargs for edm, adaptive_pid, jittered_constant, multi_channel_jittered. The registry entries exist; the from_config switch doesn't dispatch on them. The to_config → from_config round-trip silently loses configuration. (Sev 2)
